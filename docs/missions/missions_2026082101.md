# 任務需求整理

## 主要任務

補上 **Tournament + Leaderboard** 的前端 UI，讓這批功能在網頁上完整可見。

---

## 待處理問題清單

### 1. Game Lobby Table 辨識度不足
每一張 table 都長一樣，玩家入場後無法辨識自己目前在哪一張 table。
- 需優化顯示方式，讓玩家離場後能透過明顯的辨識重新回到同一張 table。

### 2. Play Again 導致無法繼續遊戲
同一張 table 結束遊戲後，點擊 **play again** 就不能再玩，畫面顯示：

```
Forbidden: missing permission games:create
```

需要釐清原因：是籌碼用完了，還是其他原因？

**修正方向：**
- 原則上每張 table 荷官應該都有預設籌碼。
- 除非該桌籌碼用完，才無法繼續遊戲。
- 若要繼續，應由 admin 補充籌碼後，再決定是否重新開放 table。

#### 2-1. Create New Game 邏輯混亂
目前點擊 create new game 時，似乎會強制把現有 table 依某種規則變成四人桌。

**建議修正：**
- 建立 table 時應跳出 panel，讓 admin 選擇要建立幾人遊玩的 table（例如提供 2 / 4 / 6 / 8 人現成選項）。
- 同時需設定該 table 的籌碼額度，透過滾碼補充；若滾碼來源金額不足，則無法補充足夠籌碼。

#### 2-2. Admin 可編輯 Table
Admin 應可編輯 table，決定是否進行滾碼補充籌碼。

#### 2-3. 無玩家時可關閉 Table 並回滾籌碼
當沒有玩家在 table 遊玩時，admin 要能：
- 關閉該 table。
- 將 table 內的籌碼回滾到主帳戶中。

#### 2-4. 重複加入同一 Table 的錯誤訊息
玩家 join game 後離開 table，再重新進入同一個 table 時，畫面顯示：

```
User cmsqwyr1p00167et857xxhl3u has already joined game cmt2b05tc00i33yb48v1ild5c
```

**需要的判斷機制：**
- 若牌局尚未結束，原本的玩家要重新入場，應允許入場。
- 若是其他玩家要入場，則須等所有玩家都結束遊戲後，其他玩家才能進入牌局。

#### 2-5. 遊戲中離場的提醒機制
玩家不得任意離場：
- 若牌局已發牌、尚未分出勝負，玩家此時離場，應彈出視窗提醒：**離場將直接扣掉手上的籌碼**。

### 3. 籌碼餘額顯示
無論玩家在 **Client Portal**、**Lobby**，還是在 **Blackjack 遊戲進行中**，都應該能看到自己目前剩餘的籌碼數量。

### 4. Client Portal Roles 顯示異常
目前 Roles 欄位顯示為重複的 `user user user user user`，研判是資料庫資料重複所致，資料庫端缺乏防呆機制，導致 `UserRole` 表中不斷寫入重複值。

**修正方向：**
- 需修正 schema，避免重複值寫入 `UserRole`。

## 後續執行方式

1. 先分析任務執行優先順序。
2. 再將任務切割為子任務。
3. 分派子任務時，**最多只能分派1個子任務同時進行**。
4. 任務切割原則：**工作越細越單純越好**。
